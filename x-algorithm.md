# Алгоритм ленты X «For You» — что важно для @lorenzofl0w

Источник: открытый код https://github.com/xai-org/x-algorithm, коммит 6258a15 от 24.10.2026.
По README значения по умолчанию в коде cron-скрипт держит равными тем, что работают в X. Эксперименты
на части аудитории могут их менять. Промпты классификатора Grox и часть правил меток не опубликованы.

Что здесь — факт из кода, а что — наш вывод, помечено. `brief.md` и `playbook.md` важнее этого файла:
это механика, а не правила аккаунта. Обновлять вручную, когда в репозитории X меняются веса
(`home-mixer/params/param.rs`, `vm-ranker/params.rs`).

## Как собирается лента (факт)

1. **Кандидаты.** Посты берутся из четырёх мест:
   - **подписки** зрителя (Thunder);
   - **похожие посты** (Phoenix retrieval): пост кодируется по содержанию (текст и медиа) и по автору,
     затем модель ищет посты, похожие на то, с чем зритель уже взаимодействовал;
   - **сообщества по интересам** (SimClusters);
   - **общий список популярных постов**.

   Посты старше 48 часов выбывают.
2. **Прогноз.** Модель Phoenix по истории зрителя предсказывает вероятность примерно 25 действий
   на каждом посте.
3. **Счёт поста** = Σ вес × предсказанная вероятность действия. Затем поправки (см. ниже).
4. **Фильтры видимости.** Посты с метками могут быть показаны с пометкой, скрыты за предупреждением
   или убраны. Часть правил убирает пост **только у тех, кто не подписан** на автора.

## Веса (факт, `home-mixer/params/param.rs`)

| Действие | Вес |
|---|---|
| Копирование ссылки | 20 |
| Ответ | 5 (20, если зритель и автор подписаны друг на друга) |
| Цитата | 5 |
| Пересылка в личку | 5 |
| Подписка на автора | 4 |
| Поделиться | 2 |
| Репост | 1 |
| Лайк | 0,66 |
| Время на открытом посте | 0,4 |
| Переход по ссылке | 0,2 |
| Время в ленте | 0,05 |
| Клик в профиль, просмотр видео, досматривание видео | 0 |
| «Не интересно» | −52 |
| Заглушить автора | −59 |
| Заблокировать автора | −31 |
| Пожаловаться | −234 |

Вес умножается на **предсказанную вероятность** действия этого зрителя, а не на число действий.
«1 жалоба = 350 лайков» — неверное прочтение: в коде об этом прямой комментарий.

Веса из кода 2023 года (ответ 13,5, «автор ответил» 75, клик в профиль 12) **устарели**, на них
не ссылаться.

## Поправки к счёту (факт)

- **Чужой аккаунт: ×0,75.** Посты аккаунтов, на которые зритель не подписан, умножаются на 0,75.
- **Разнообразие авторов.** Если в одной выдаче несколько постов одного автора: второй ×0,625,
  третий ×0,44, дальше меньше, минимум ×0,25. Дополнительно похожие посты разносятся подальше друг
  от друга.
- **Холодный старт для небольших авторов** (`home-mixer/scorers/author_cold_start.rs`).
  - Условия: у автора до 50 000 подписчиков, посту меньше 2 часов, у него меньше 200 показов в ленте.
  - В каждой выдаче один такой пост поднимают примерно на 15-ю позицию.
  - Выбор случайный, но с учётом доли лайков от показов. Стартовое ожидание — около 1,5% лайков.
  - Механизм оформлен как эксперимент с контрольной группой, но включён.
- **Буста Premium / галочки в ранжировании нет.**
- **Внешние ссылки отдельно не штрафуются** (переход по ссылке даёт +0,2).
- Среди меток классификатора есть «приманка для вовлечения» (`SpamEngagementBaiting`). По каким
  признакам её ставят, не опубликовано. Метки, которые висят на аккаунте и постах, показывает
  инструмент Under the Hood: https://x.com/i/jf/under_the_hood.

## Метка SpamHighRecall и ответы

**Факт из кода** (`abuse-enforcement-service/service-lib/rules/`):
- Пока на аккаунте висит метка `SpamHighRecall`, его посты не показываются в рекомендациях тем,
  кто не подписан. У этого аккаунта это почти весь охват.
- На аккаунт метку ставят правила по сигналам классификаторов:
  - спам-ответы бота (`bb1_reply_spam_bot_bounce`) — 30 дней и проверка, что аккаунтом управляет
    человек;
  - ИИ-текст (`llm_slop_user`) — 7 дней;
  - однотипные посты, похожие на спам (`SpamEmbeddingMajorityPoster`) — 30 дней;
  - общие спам-сигналы — 7 дней.
- На отдельный пост метку ставят за быстрые ответы, похожие на спам (`fast_reply_spam_post` →
  `SpamHighRecall`), и за ИИ-текст в ответе (`llm_slop_post` → `RiskyHighVizReply`).
- От проверок освобождены аккаунты с большим числом подписчиков или высокой «репутацией» (PageRank).
  Настоящие пороги в открытом коде заменены фиктивными.

**Случай аккаунта.** Отчёт Under the Hood за сентябрь 2026: `SpamHighRecall` 5 дней из 30.
Причина, по словам Полины, — массовые ответы под чужими постами. Эти ответы удалены.

**Правила для ответов:**
1. Под своими постами отвечать безопасно и полезно: ответ весит 5, для взаимных подписчиков 20.
2. Под чужими постами отвечать только по делу, руками и каждый раз разным текстом. Без серий
   за несколько минут, без одинаковых фраз, ссылок и шаблонов.
3. Ответы ИИ не пишет: черновики ответов в этом репозитории не готовим.
4. Если охват резко упал, сначала смотреть отчёт Under the Hood, потом делать выводы о теме и времени.
   Отчёт за месяц появляется примерно 7-го числа следующего месяца.

## Для author (наши выводы из механики)

1. **Первая строка решает холодный старт.** В первые 2 часа и первые 200 показов пост проверяют
   на доле лайков. Хук должен вызывать лайк у незнакомого человека: почти весь охват аккаунта —
   не подписчики (по X Analytics за 28 дней — 100% показов).
2. **Пост должен вызывать желание подписаться.** Прогноз «подпишется ли» весит 4, в 6 раз больше
   лайка. История должна заканчиваться так, чтобы захотелось ещё таких историй.
3. **Пиши так, чтобы хотелось переслать.** Копирование ссылки весит 20, пересылка в личку 5.
   59% пересылок аккаунта делают люди 55+: «перешлю это знакомому».
4. **Вопрос в конце работает через ответы** (вес 5). Вопрос с выбором стороны даёт больше ответов,
   чем вопрос «да/нет».
5. **Без приманок для вовлечения.** Никаких «Like + comment X & I'll DM», «Must follow for DM»,
   «Follow for more». Отрицательные реакции весят −52…−234, а метка приманки может убрать пост у
   всех, кто не подписан, то есть почти у всей аудитории.
6. **Держись темы аккаунта.** Похожие посты ищутся по содержанию и по автору: постоянная тема
   «деньги + знаменитость» закрепляет за аккаунтом аудиторию, которой такие посты уже нравились.
7. **Видео помогает косвенно.** Прямого веса у просмотра видео нет. Ролик работает через время
   на посте и через то, что пост цепляет, поэтому строка-указатель на видео должна обещать что-то
   конкретное.
8. **Текст не должен читаться как ИИ.** Существует метка `llm_slop_user`, а черновики здесь пишет
   ИИ. Ломай повторяющиеся конструкции («It is not A. It is not B.», одинаковые финалы), меняй
   структуру от поста к посту, а не только героя. Однотипные посты дают риск метки
   `SpamEmbeddingMajorityPoster` (30 дней).

## Для coach (наши выводы из механики)

1. **Посты одного вечера мешают друг другу.** Все посты живут 48 часов и попадают в одни выдачи, где
   второй получает ×0,625, третий ×0,44. Эксперименты, где за 1–3 часа выходит 2–3 поста (например,
   вариант B в E1), сравнивают не честно. Лучше один пост в окно и больше недель.
2. **Главная метрика — подписки на 1 000 показов**, а не просмотры: подписка входит в счёт поста.
   По X Analytics (разбор `analytics/what-works-2026-10-24.md`) просмотры с подписками связаны слабо.
3. **Ранний сигнал** — доля лайков от показов в первые 2 часа против порога ~1,5%. Пост ниже порога
   почти наверняка не выйдет из холодного старта.
4. **Если пост внезапно не набирает охват**, сначала проверь Under the Hood: не висит ли метка.
   Выводы о теме и времени делай только после этого.
5. **Правила playbook о механике** (например, «без приманок для вовлечения») ссылаются на этот файл,
   но статус «подтверждено» получают только по цифрам аккаунта, как и все остальные.
