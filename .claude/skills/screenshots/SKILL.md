# /screenshots — цифры из X Analytics

**Только интерактивно.** Если запущен через `claude -p` или скриншотов в диалоге нет — ничего не записывать,
напечатать «/screenshots работает только в диалоге со скриншотами» и закончить.

## 1. Распознать

Для каждого скриншота определить:
- что это: пост (какой — по тексту, дате, ссылке) или профиль/аккаунт за период;
- дату или период, к которому относятся цифры;
- цифры: показы (impressions), вовлечения, лайки, ответы, репосты, закладки, визиты профиля,
  подписки (new follows), число подписчиков, а также раскрытия (detail expands), шеры (shares), просмотры
  видео, переходы по ссылкам и доля показов подписчикам и не подписчикам, если они видны на скриншоте;
- возраст замера: сколько часов прошло с публикации поста до скриншота (время поста — из `my_posts`,
  разницу считать через `node scripts/now.mjs`). Нормальный замер — 24–48 часов.

Пост сопоставить с постом аккаунта через `my_posts` / `search_posts` (ссылка или первые слова) и с черновиком
по `edits.md`. Не уверен — так и написать в таблице.

## 2. Показать и дождаться подтверждения

Таблица:

| Скриншот | Пост / профиль | Дата | Показы | Лайки | Визиты профиля | Подписки | Подписчики | Куда запишу |
|---|---|---|---|---|---|---|---|---|

В колонке «Куда запишу» — `analytics/<неделя>.md`, `record_post_metrics (<id черновика студии>)`,
`record_profile_analytics (<дата>)`. Спросить: «Цифры верные? Записываю?» — и **ждать ответа**.
Полина правит — исправить таблицу и показать снова. Без явного «да» ничего не писать.

## 3. Записать после подтверждения

1. **analytics/** — в файл недели, в которую **опубликован** пост (`node scripts/now.mjs <время поста>` →
   `isoWeek`). Заполнить колонки «Показы», «Визиты профиля», «Подписки» в строке поста. Файла нет — создать
   с заголовком недели и таблицей, где только этот пост; /analyst-weekly дополнит.
1a. **data/post-analytics.md** — добавить строку поста (если уже есть, дополнить) со всеми цифрами скриншота и
   возрастом замера. Поля, которых на скриншоте нет, оставить пустыми, не нулями. Этот файл — основа для
   вопроса «что запускает пост в первые часы»: по нему сверяются шеры, раскрытия и доля не подписчиков с
   кривой просмотров (`data/my-posts.md`, раздел «Первые часы»).
2. **record_post_metrics** — только если у поста есть черновик в студии сервиса: найти его в `own_published`
   (по `postId` или тексту). Нет черновика студии — не записывать в сервис, только в analytics/.
3. **record_profile_analytics** — только цифры, которые относятся к конкретной дате: число подписчиков на
   дату скриншота, визиты профиля и подписки за один день. Цифры за 7/28 дней в дневной срез не писать —
   их место в analytics/.

После записи показать, что ушло в сервис (ответы инструментов).

## 4. Коммит

```
git add analytics/ data/post-analytics.md
git commit -m "screenshots: цифры X Analytics за <даты>"
```
