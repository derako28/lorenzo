# /competitors — разбор чужих постов

Работает и интерактивно, и через `claude -p`. **Вопросов не задавать**: чего не хватает — в раздел
«Нужно от Полины» итогового файла, и идти дальше. Аргумент `no-commit` — всё сделать, но не коммитить.
Идёт за полчаса до `/daily`, чтобы author видел свежие паттерны.

## 1. Дата и состояние

- `node scripts/now.mjs` → `date`, время по Варшаве и ET.
- Итоговый файл: `competitors/<date>.md`. Если уже есть — не затирать: дописать блок «Прогон HH:MM».
- Прочитать `brief.md` (темы, табу), `competitors/patterns.md` (если есть) и последний файл
  `competitors/`: уже разобранные посты (по id) повторно не разбирать, а у паттернов обновлять счётчики.
- `experiments.md` (раздел «Активный») — чтобы в «Что взять» учесть, что проверяется сейчас.

## 2. Что отдать агенту `competitor`

Вызвать агента `competitor` с заданием:

- Обычная выборка: `top_posts` (workspace: "finance", days: 2, sort_by: "views", limit: 20) и
  `rising_posts` (hours: 48, limit: 15). Для накопления выборки в паттернах — ещё `top_posts` за 7 дней
  по просмотрам, если в `patterns.md` у приёма меньше 5 постов.
- Вирусные: посты ниши с 1 000 000+ просмотров за 48 часов (режим из описания агента). Окно поиска —
  7 дней, чтобы замеры в первые 48 ч уже были в истории.
- Исключить id, уже разобранные в прошлых файлах `competitors/`.
- Дату файла и путь передать агенту (у него может не быть Bash).

Новых постов нет — файл всё равно создать с короткой записью «новых постов для разбора нет» и пройти
к коммиту. Инструмент упал — в «Нужно от Полины»: какой и с какой ошибкой; выдуманных постов не добавлять.

## 3. Итоговый файл `competitors/<date>.md`

Формат — из раздела «Что вернуть» агента `competitor`, плюс шапка:

```
# Разбор чужих постов — <date> (<день недели>)

Сгенерировано: <время Варшава> / <время ET>
Выборка: <сколько взято, сколько вирусных 1 млн+, сколько отброшено>
```

Затем разделы агента: «Вирусные 1 млн+ за 48 ч», «Карточки», «Паттерны», «Что взять в ближайшие посты»,
«Предложения (для coach)», «Нужно от Полины».

`competitors/patterns.md` — обновить: счётчики, статусы, дата обновления у каждого затронутого приёма.
Без числа постов и цифр приём не записывать.

## 4. Коммит

Если не `no-commit`:

```
git add competitors/
git commit -m "competitors: разбор <date>"
```

Только каталог `competitors/`. Не пушить. В конце напечатать короткую сводку: сколько постов разобрано,
сколько вирусных, новые и сдвинувшиеся паттерны, «Нужно от Полины».
